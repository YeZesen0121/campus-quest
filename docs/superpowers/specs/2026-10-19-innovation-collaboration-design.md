# R6 项目协作与生命周期设计

日期：2026-10-19。业务规则已在本次对话中逐项确认，并完成用户视角审查、书面一致性复核及修订。小叶随后明确表示“我没空审阅，合理的话可以开干了”，授权代理自行审查设计和实施计划，合理即继续执行，不再以等待逐文档审阅为前提。本设计经代理复核可作为 R6 实施基线；下一步先形成并自审实施计划，再在独立工作树实施。本工作树已进入 R6 实施，具体已实现及未完成范围见对应实施计划、验证账本和实施交接；设计共识不因阶段状态变化而改变。没有自动推送或合并授权。

## 1 目标与范围

让负责人能够邀请同学协助维护项目、取得成员公开挂名同意、向有资格的接任者交接项目，并在结项后继续保留和整理公开项目经历。受邀者应能找到待办，知道自己接受了什么；退出、撤权、冲突和网络结果未知时均有明确去向。

本轮覆盖共同管理、成员挂名、负责人转让、逐份证明交接、项目结项与恢复、结项公开介绍维护，以及完整参与关系的成果审核回避。沿用 R1–R5 的负责人资格、成果全量更新复审、招募独立免审、人才主动展示、导师本人授权与项目独立挂名规则。

不纳入站内投递、简历、录取、私聊、导师预约、积分激励、完整举报申诉工作台、学校 SSO 或重新选择全站视觉风格。学校 SSO 仍最后接入，演示身份与资料明确标注为模拟。

## 2 业务共识与修订

| 决策 | 已确认规则 |
| --- | --- |
| Q1 共同管理 | 可维护项目介绍及招募，准备成果文字草稿；正式成果提审、团队授权、转让与结项仍由负责人操作；管理权不自动包含证明读取权 |
| Q2 原负责人 | 转让后退出管理，需要继续协助时由新负责人重新邀请，不隐式保留管理身份 |
| Q3 结束关系 | 成员本人或负责人可结束当前挂名；公开立即撤下，必要参与历史内部保留；共同管理员可主动退出或被撤权 |
| Q4 结项 | 关闭现有招募、保留成果，允许继续补充成果并按原规则审核；重新招募前明确恢复进行中 |
| Q5 待审与转让 | 有待审成果时先办结或主动撤回，再完成转让 |
| Q6 已有关系 | 转让保留其他已接受的成员、共同管理员及导师关系；未确认邀请失效；接任前展示现有关系与授权范围 |
| Q7 证明交接 | 原负责人逐份选取可移交的项目证明，接任者确认范围；原负责人资格资料不移交；未选证明仅按原审核关系留存，不向接任者开放 |
| Q8 招募交接 | 转让生效时关闭现有招募；新负责人随后核对岗位、截止时间与联系授权，再明确重新开放 |
| Q9 公开字段 | 只展示本人确认的公开姓名与项目分工；变更需再次确认，期间保留旧版；管理授权与公开挂名分别同意 |
| Q10 结项档案 | 原本已公开但暂无已核实成果的项目，结项后保留最后公开介绍，明确标注状态，成员与导师按当前有效同意展示 |
| Q11 接任前查阅 | 原负责人明确授权后，指定接任者可提前只读查阅选定项目证明；取消、拒绝或过期后停止后续读取 |
| Q12 更正结项介绍 | 增加修改、预览、明确发布结项项目介绍的路径，保留修改记录、核实状态说明及原审核历史 |

Q11 覆盖 Q7 中最初建议的“接任后才可读取”时点，不能将这两种时点同时作为现行规则。提前查阅不等于接受转让，不授予项目编辑权；发出授权时明确提示查阅可能包含下载，取消只能阻止后续请求，不能收回已经下载的文件。

用户视角审查同时确认补齐邀请与本人入口、权限说明、两种退出、待审锁定后的输入保留、交接结果查询、关闭岗位的恢复入口，以及回避后重新分配的流程。它们是本轮交付组成部分。

## 3 权限与数据边界

| 主体 | 可执行 | 不自动获得 |
| --- | --- | --- |
| 当前负责人 | 本项目维护、成果提审、本人当前获权的证明管理、招募、成员与共同管理授权、导师挂名管理、转让、结项及恢复 | 他人项目权限、未获交接授权的历史证明、运营审核权、任意个人资料公开权 |
| 已接受的共同管理员 | 指定项目介绍、招募草稿与日常维护、成果文字草稿准备；主动退出 | 负责人资格、正式成果提审、证明清单与内容、团队授权、导师关系管理、转让、结项与恢复 |
| 已确认成员 | 查看本人关系、确认或拒绝公开候选、撤下本人挂名 | 项目私有工作区、编辑权、证明读取权 |
| 待接任者 | 查看负责人明确提供的项目摘要、关系与权限清单；按明确授权查阅选定证明；接受或拒绝转让 | 全部私稿、未选证明、原负责人资格资料、编辑权 |
| 获授权运营 | 在无利益冲突并按现有领取规则获得权限后核实具体成果 | 本人参与项目的核实权、项目全部草稿或全部材料 |
| 普通校内浏览者 | 读取可见项目介绍、已通过成果、有效岗位及当前获同意的公开成员和导师 | 待审稿、私稿、身份核实资料、私密证明、内部参与历史 |

共同管理员准备文字草稿不要求负责人资格。发布、更新公开招募和重新开放沿用 R3 的“本人负责人资格有效且具有对应项目权限”要求；邀请和工作区提前说明，无资格者可准备草稿、关闭已有招募，再交负责人发布。对合资格共管，分别校验操作者的有效资格与已接受管理权，以及项目当前负责人和岗位的既有公开条件；不能把操作者误限定为 owner。账号、资格、关系及公开条件均在后端重新校验，不能只开放按钮或仅改写入口。

联系方式沿用 R3 的岗位级明确授权：不自动取账号绑定信息，不因管理授权或转让默认扩展使用同意。发布预览展示本次将公开的岗位与联系范围，输入者确认是本人或已取得使用同意的项目联系渠道；系统不宣称替第三方完成了同意核验。

姓名、学号、专业、年级的负责人资格快照保持私有。公开挂名姓名由本人确认，不从资格快照自动填入公开响应。共同管理员、成员和导师关系不使私有项目自动公开。

## 4 邀请与本人待办

负责人在已保存项目中发出定向邀请。使用已知本校账号精确定位目标，不提供全校人员名册或模糊学号搜索结果；输入不写入 URL、通知或普通日志，确认响应只返回必要的公开称呼与不透明目标引用，不回传学号或四项资格资料。仅目标账号本人登录后可接受、拒绝，链接持有人不能代替本人确认。

“我的项目”提供本人可达的我负责的、我共同管理的、我的挂名、待我确认及相关处理结果入口。普通成员和已退出管理者无需先取得项目编辑权，就能处理自己的挂名或查询自己的交接结果。列表明确分页，不静默截断旧待办和历史。

邀请页展示项目摘要、邀请用途、将授予的能力、是否另有公开挂名候选及失效时间。同意选项默认不勾选；拒绝、撤销与过期不产生权限。公开挂名与共同管理分开确认，不用一个“加入项目”按钮同时授予编辑权并公开姓名。

每份邀请有版本和明确的 `expires_at`；业务时间使用可注入 Clock，`now >= expires_at` 即不可接受或继续提前查阅，不依赖后台任务准时执行。有效期数值作为工程配置在实施计划固定，并覆盖边界测试，不作为学校制度。修改目标或已发出的范围需形成新的确认版本，旧确认不能作用于新内容。

站内待办是可用入口，通知只是可发现性的补充；新增通知必须走持久投递意图与现有真实组合，不发送未获本轮授权的短信或邮件，不伪造成功通知。

## 5 共同管理与公开挂名

### 5.1 协作编辑

共同管理员只读写被授权的文字字段，不通过“项目详情”响应旁带证明、负责人快照或未授权联系资料。成果文字草稿与证明服务分开鉴权，不能把所有现有 owner 检查统一放宽为“可管理项目”。

多人编辑沿用版本冲突规则：旧版本保存失败时保留本地输入，展示当前服务器内容，明确区分重新加载与覆盖本人输入。负责人提交前核对已保存版本；提交后只锁该份成果和证明，项目草稿不随之整体锁定。迟到保存不得覆盖已提交快照，并给出联系负责人等待审核或撤回后继续的路径。

### 5.2 挂名候选与退出

公开字段限定为本人确认的公开姓名和项目分工，候选内容绑定具体版本。修改后形成新候选，确认前继续显示旧同意版；拒绝新候选不自动撤下旧版。本人或负责人结束当前挂名时立即停止展示，待定修改不能在以后重新恢复旧关系。

共同管理与挂名是两个独立关系：按钮分别使用“退出共同管理”“撤下公开挂名”，说明动作后是否仍有编辑权或仍公开姓名。共同管理员撤权不暗中替本人同意或撤下挂名，撤下挂名也不隐式解除管理权。历史参与记录内部保留，不向普通浏览者公开。

## 6 负责人转让与证明交接

### 6.1 发起与提前查阅

当前负责人选择有效、已具负责人资格的本校接任账号。页面列出阻塞转让的待审成果及其处理入口，允许先等待办结或主动撤回；不通过转让自动撤销成果审核，不改写审核历史。最终接受时还要重新检查没有待审成果。

负责人逐份选择自己当前有权交接的项目证明，明确是否向该指定接任者开放提前查阅；同时提供项目摘要、生命周期、已接受的管理与挂名关系，以及将关闭的招募清单。选择材料不等于可以泄露文件中不适合交接的个人信息；需要处理时提供新的适合交接版本，原审核引用不能被替换以改写历史。

接任者确认前可读取上述摘要和清单，仅在明确提前授权有效时主动查阅选中证明，不预取文件。请求逐次验证目标本人、账号、资格、邀请版本、有效期、当前负责人和材料范围；每次敏感读取先持久审计，失败时不返回文件。实际主动查阅同时纳入该项目的利益冲突历史，并处理其可能持有的审核领取，不允许一边按接任者查阅、一边继续核实同一项目。仅由负责人单方面发出邀请或查阅授权不认定对方已经参与。复用受控下载代理，不输出对象 key 或可绕过撤权的签名链接。

### 6.2 接受与原子生效

最终确认展示接任后果及具体移交范围。项目摘要、生命周期、独立公开介绍版本、团队授权、选中证明或招募清单在确认期间变化时，展示差异并要求对当前版本重新确认；最终接受绑定这些当前版本，不因为发起转让而冻结整个项目编辑器。

转让在一个服务事务中重新检查发起者仍为负责人、双方账号及接任资格有效、没有待审成果、内容版本一致，然后共同完成：

1. 更新当前负责人并保留不可变创建者、提交者及转让历史。
2. 终止原负责人的管理身份；不能因遗留的共同管理记录在以后重新取得权限。
3. 保留其他已接受的共同管理、成员和导师关系，作废本项目未确认的共同管理、成员及导师挂名邀请和其他未完成转让请求；不影响其他项目或导师档案本人的确认流程。
4. 将选中证明转为接任者在本项目内的明确读取范围，不移动或重写原审核证据、上传者和资格快照；未选证明不向接任者开放或供其复用。
5. 关闭现有招募，使旧岗位及联系读取立即按关闭状态拒绝；终止转让阶段的临时查阅授权。
6. 写入持久审计和双方可查询的操作结果；相关通知按现有持久投递机制处理。

新负责人提交后续成果时使用自己的有效资格资料和当前有权使用的证明，不沿用旧负责人的资格快照冒充自己的提交。同一项目并发转让最多一次生效；重试不能重复转让或恢复已失效邀请。

### 6.3 成功与结果未知

双方看到“核对中、已完成、已失效”等明确状态。原负责人失去项目权限后，仍能在自己的交接记录查询最小结果，不能借查询结果继续读取现项目私稿、证明或联系方式。断网重试保持原命令及原载荷，先核对结果，不因管理接口变为无权限就误判转让失败。

新负责人的完成页提供已关闭岗位的逐项恢复入口，核对联系授权、截止日期和内容后明确重新开放；原负责人完成页只显示最小交接结果，说明继续协助需由新负责人重新邀请，不导向已失权的管理页。转让向导内不追加岗位联系编辑流程。若项目仍进行中且原本只靠招募公开，转让关闭最后岗位后沿用现有公开条件，可能暂时退出公共列表；新负责人仍可管理并重新开放。本段不把转让偷偷解释为结项或自动创建结项档案。

## 7 结项与公开项目档案

项目生命周期与成果审核状态、招募状态分别记录，不能复用原自由填写的阶段字段。结项确认列出将关闭的岗位和公开页后果；生效后关闭现有招募，保留已通过成果及有效同意的成员、导师。

原本已公开但没有已核实成果的项目，保存此前明确公开的介绍白名单版本作为档案来源，标明“已结项”“暂无已核实成果”。从未公开的项目不能借结项首次公开，私有草稿或未通过成果不能成为档案源。原公开来源被明确下架时，不得借留档继续展示被隐藏的内容；编辑、恢复或再次结项也不清除治理状态。

负责人可以补充成果，仍完整执行首次核实或更新复审；待审时保留旧公开成果。项目介绍维护另提供“更新结项项目介绍”：修改白名单字段、预览、明确发布，创建新公开介绍版本并保留修改记录。共同管理员可整理相关文字草稿，结项档案的明确公开发布仍由当前有效账号、具有效负责人资格的负责人操作，继续检查档案及原来源的治理限制。恢复进行中后的档案介绍发布沿用相同条件。它不是成果审核，不写入虚假的核实标记，不改历史成果快照。

独立档案介绍生效后，项目页明确说明当前介绍来源；已有成果继续展示各自实际已审核版本和时间。项目成员与导师从当前有效同意读取，不冻结为介绍发布当时的人名。结项状态、是否正在招募和具体成果核实事实分别表达，不能给整页加一枚“已认证项目”标记。

负责人明确恢复进行中只改变生命周期，不自动重开岗位、不恢复旧授权、不公开私稿。已经明确发布的档案介绍继续作为可见来源，避免恢复后项目再次消失；新岗位需核对并另行开放，后续介绍更新仍通过明确预览发布路径。此路径不扩展为普通私有项目无需来源即可首次公开。

## 8 完整参与人审核回避

当前和历史负责人、已接受的共同管理员、已确认成员、已同意项目挂名的导师进入真实参与历史；待接任者实际主动查阅证明也形成利益冲突历史。成员退出、撤权、转让、撤下公开姓名或结束临时查阅，不删除既有回避依据；未接受邀请不单凭收到邀请或单方面获得查阅授权认定已参与。既有主动声明其他利益冲突的能力保留。

队列、领取、详情、证明下载与最终审核决定使用相同关系判定，不只在列表隐藏按钮。运营已领取后因新关系需要回避时，停止其后续材料读取和决定权限，释放或返回待分配队列；没有无冲突人员时明确交由管理员协调合资格审核人，不跳过核实，也不默认给管理员全部材料读取权。已经合法完成的历史决定不被静默改写。

## 11 交付验收场景

以下是未来实现的验收要求，不是已执行或通过的测试记录。规约预期先进入对应矩阵，再绑定实际测试；数据库不变量使用真实 PostgreSQL 独立连接验证。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| C01 | 目标尚未接受共同管理邀请 | 无编辑权；其他账号不能代接受 |
| C02 | 共同管理与公开挂名分别确认 | 可只接受管理或只同意挂名；无隐式捆绑 |
| C03 | 无资格或有资格的共管准备招募 | 前者可存稿并交负责人发布；后者满足本人资格、已接受管理权及项目公开条件后可发布，不被误判为必须是 owner |
| C04 | 共管尝试证明、提审、授权、导师管理或转让 | 对应私有字段不返回，未授权动作被后端拒绝 |
| C05 | 多人修改与负责人提交竞争 | 只提交已保存一致版本；失败不覆盖新稿，本地输入保留 |
| C06 | 姓名或分工改候选，目标拒绝或尚未确认 | 旧有效公开版保留；未同意新内容不展示 |
| C07 | 任一方结束挂名或撤回管理 | 对应展示或权限即时失效，另一种关系独立；旧请求不恢复关系 |
| C08 | 目标从本人入口查待办、历史和退出操作 | 无需项目编辑权即可处理本人的事项；分页可达 |
| C09 | 转让时存在待审或接任资格失效 | 阻止生效，指出具体阻塞事项和处理路径 |
| C10 | 接任前明确授权提前查阅 | 仅指定目标、选中证明、有效期限与版本可读；资格资料与未选证明不可读；主动查阅触发回避，单方面发邀不触发 |
| C11 | 取消、拒绝、过期、换目标或改材料后重放 | 旧查阅与旧确认失效，原审核证明和历史不被改写 |
| C12 | 并发转让及转让与保存、结项恢复、介绍发布、导师邀请、提审竞争 | 最多一次转让成功；内容或生命周期变化需重新确认，锁后重验当前权限，不发生旧负责人迟到写入 |
| C13 | 转让完成 | 原负责人失去管理；选中证明按范围交接；其他已接受关系保留；未确认邀请失效；招募关闭 |
| C14 | 原负责人重试旧创建请求或接任者请求键相同 | 不额外创建、不误用接任者的创建收据、不改变原创建指纹；原负责人不得取得现项目私稿、证明或联系方式 |
| C15 | 接任成功回执丢失或换页返回 | 双方可查询自己的最小结果并安全重试；原负责人仅看结果，新负责人有岗位恢复入口，不恢复旧管理权或泄露现项目私稿 |
| C16 | 新负责人恢复招募 | 核对当前内容、未来截止时间及联系授权后明确开放，旧联系不默认继承 |
| C17 | 仅招募公开的项目结项 | 招募关闭，最后公开介绍保留；显示无已核实成果，不出现私稿或虚假核实标记 |
| C18 | 从未公开项目结项或原来源被下架 | 不借结项首次公开，不通过留档或恢复绕过下架 |
| C19 | 更正结项介绍与继续补充成果 | 介绍由资格有效的当前负责人先预览再发布并保留版本；治理限制不被绕过，成果仍按原流程核实，旧审核快照不变 |
| C20 | 恢复进行中 | 档案介绍仍可见，岗位仍关闭，未重新同意的关系或联系不复活 |
| C21 | 历史参与人或新加入关系触发运营回避 | 队列、领取、详情、下载、决定一致拒绝；已领取事项回待分配并有后续协调去向 |
| C22 | 手机、键盘、错误、断网、换号和迟响应 | 操作可达，输入与原命令按范围恢复，私有数据不跨账号残留，确认与返回焦点明确 |
